# Xserver 導入手順書

接骨院 LINE 一括配信（Xserver 版）を、Xserver のレンタルサーバーに設置する手順です。
**所要時間の目安：30〜40 分**（FTP でのアップロード、データベース作成、インストーラー、cron 設定）。

> サーバーパネルの画面名・配置は変更されることがあります。見つからない場合は、近い名前のメニューを探してください。

## 動作要件

| 項目 | 内容 |
|---|---|
| サーバー | Xserver（レンタルサーバー）の通常プラン。**SSH・Node.js は不要** |
| PHP | 8.1 以上（8.2 推奨）。サーバーパネルの「PHP Ver.切替」で設定 |
| データベース | MySQL（Xserver 標準）。MariaDB でも可 |
| PHP 拡張 | PDO MySQL / cURL / OpenSSL / mbstring（Xserver は標準で有効） |
| HTTPS | **必須**（LINE の Webhook は HTTPS のみ）。「無料独自SSL設定」で設定 |
| 定期実行 | サーバーパネルの「Cron設定」（1 分ごと） |

## 0. 準備：設置先を決める

設置先は次のどれでも動きます。**サブドメインは必須ではありません。**

| 設置先 | 例 | 向いているケース |
|---|---|---|
| サブドメイン（おすすめ） | `https://line.example.com/` | ほかのサイトと完全に分けたい。のちの引っ越しも簡単 |
| ドメイン直下 | `https://example.com/` | そのドメインを本システム専用に使う（ホームページがあるドメインには不向き） |
| サブフォルダ | `https://example.com/line/` | ホームページがあるドメインに追加で置く（下の「サブフォルダに設置する場合」参照） |

> **「URLを知っている人だけ」が使える**ようにするため、サブドメインでもフォルダでも、本システムには **アクセスキー** が付きます（インストール時に自動生成）。
> キー付きの URL を開いた端末だけがログイン画面を見られ、知らない人には「存在しないページ（404）」と表示されます。さらに検索エンジンにも載りません。詳しくは下の「外部から見つからないようにする」を参照してください。

サブドメインを使う場合：

1. サーバーパネル →「ドメイン設定」→「サブドメイン設定」で `line`（など）を追加
2. 「SSL設定」→ 対象ドメインで「無料独自SSL設定」を追加（反映に数分〜1時間ほどかかることがあります）
3. 「PHP Ver.切替」→ 対象ドメインを **PHP 8.2**（8.1 以上）にする

ドメイン直下・サブフォルダの場合も、2（SSL）と 3（PHP バージョン）は同様に設定してください。

## 1. データベースを作る

1. サーバーパネル →「MySQL設定」→「MySQL追加」で、データベースを作成（例：`xxxx_linehub`）
2. 「MySQLユーザ設定」→「MySQLユーザ追加」で、ユーザーとパスワードを作成
3. 「MySQL設定」→「アクセス権限未所有ユーザ」から、作成したユーザーを **データベースに追加**（権限はすべて）
4. 次の 3 つを控える（インストーラーで使います）
   - **MySQL ホスト名**（「MySQL設定」画面に表示。`localhost` ではなく `mysqlXXXX.xserver.jp` の形式のことがあります）
   - データベース名
   - ユーザー名とパスワード

## 2. ファイルをアップロードする

Xserver では、ドメインごとに次のようなフォルダ構成になります。

```
/home/サーバーID/line.example.com/
 ├─ public_html/        ← Web に公開されるフォルダ（ドキュメントルート）
 └─ app/                ← ★ここにアプリ本体を置く（Web から見えない場所）
```

FTP ソフト（FileZilla など）で、このプロジェクトの内容を次のようにアップロードします。

| このプロジェクトのフォルダ | アップロード先 |
|---|---|
| `public/` の**中身すべて**（`index.php`, `install.php`, `.htaccess`, `assets/`） | `/home/サーバーID/line.example.com/public_html/` |
| `app/` フォルダ**ごと** | `/home/サーバーID/line.example.com/app/` |

**重要**
- `.htaccess`（ドットで始まるファイル）も忘れずにアップロードしてください。FTP ソフトの設定で「隠しファイルを表示」にします。
- `docs/` `tests/` `build/` はアップロード不要です。

### サブフォルダに設置する場合（例：`https://example.com/line/`）

`public/` の中身を `public_html/line/` に、`app/` フォルダを **`public_html/line/app/`** にアップロードします。
`app/.htaccess` により `app/` 内は Web から直接見られないようになっています（Apache の設定を変更しないでください）。
なお、この場合のインストーラーの「公開URL」は `https://example.com/line` とします。

## 3. 書き込み権限を確認する

次のフォルダは PHP から書き込める必要があります（Xserver では通常、初期状態のままで書き込めます）。
書き込めない場合は、FTP ソフトでパーミッションを `705`（または `755`）にしてください。

- `app/`（インストーラーが `config.php` を作ります）
- `app/storage/media/`（配信用の画像）
- `app/storage/logs/`（cron の動作記録）

## 4. インストーラーを実行する

1. ブラウザで `https://line.example.com/` を開く → 自動で **セットアップ画面**（`install.php`）になります
2. 「動作環境のチェック」がすべて ✔ であることを確認（✘ があれば、上の手順 3 や PHP バージョンを見直す）
3. 次を入力して「セットアップを実行」
   - **データベース**：手順 1 で控えた MySQL ホスト名・データベース名・ユーザー名・パスワード
   - **公開URL**：`https://line.example.com`（実際にアクセスする URL。末尾のスラッシュなし）
   - **管理者**：ログインに使う **ログインID**（半角英数字 3〜50 文字。例：`admin`）とパスワード（8 文字以上）
4. 「セットアップが完了しました」と表示されたら成功です。
   - **「あなた専用のアクセス用 URL」が表示されます（例：`https://line.example.com/?k=xxxxxxxx…`）。必ず控えてください。**
     この URL を最初に開いた端末だけが、ログイン画面を見られるようになります（後から管理者画面の「LINE アカウント管理」でも確認できます）。
   - `install.php` は自動削除されます。**表示された警告に従い、削除されていなければ FTP で必ず削除してください。**
   - 暗号化キー（`app/config.php` の `app_key`）が自動生成されます。**このキーを紛失すると、保存済みの LINE トークンを復号できなくなります**（バックアップに `config.php` を含めてください）。

## 5. 定期実行（cron）を設定する

予約配信・ステップ配信は、**1 分ごとに動く定期実行**で送信されます。設定しないと、予約した時刻になっても送信されません。

1. サーバーパネル →「Cron設定」→「Cronの追加」
2. 次のとおり設定
   - 分・時・日・月・曜日：**すべて `*`**（毎分）
   - コマンド：

     ```
     /usr/bin/php8.2 /home/サーバーID/line.example.com/app/cron.php
     ```

     - `php8.2` は、手順 0 で選んだ PHP のバージョンに合わせます（例：8.1 なら `php8.1`）。
     - 「サーバーID」「ドメイン」は、FTP で見えるフォルダ名と同じです。
3. 保存後、数分待って、本システムのダッシュボードを開きます。
   **赤い「定期実行（cron）が動いていません」の警告が出ていなければ成功**です（警告は管理者だけに表示されます）。

> cron の実行結果メールが大量に届く場合は、「Cron設定」の通知メール設定で宛先を空にするか、コマンドの末尾に ` > /dev/null 2>&1` を付けてください。動作状況は、ダッシュボードの警告で確認できます。

## 6. LINE アカウントを接続する

[アカウント接続手順書](アカウント接続手順書.md) に従って、各店舗の LINE 公式アカウントを接続してください。

## 7. 運用・メンテナンス

### バックアップ（定期的に）

| 対象 | 方法 |
|---|---|
| データベース | サーバーパネルの「phpMyAdmin」→ 対象 DB →「エクスポート」。または Xserver の自動バックアップ（「バックアップ」機能）を利用 |
| 配信用の画像 | FTP で `app/storage/media/` をダウンロード |
| 設定ファイル | FTP で `app/config.php` をダウンロード（**暗号化キーを含むため、安全な場所に保管**） |

### 引っ越し・復旧

新しいサーバーで 2〜5 の手順を行い、インストーラーを使わずに `config.php` を復元し、データベースを取り込みます。`app_key` が同じなら、保存済みの LINE トークンはそのまま使えます。

### アップデート

新しいバージョンのファイルを FTP で上書きアップロードします（`app/config.php` と `app/storage/` は上書きしないこと）。
データベースの変更が必要な場合は、そのバージョンに SQL ファイルが付属します（phpMyAdmin の「インポート」で実行）。

### 外部から見つからないようにする（検索されない・URLを知る人だけ）

| 対策 | 内容 |
|---|---|
| **アクセスキー（入口の保護）** | キー付き URL を開いた端末（ブラウザ）だけが、ログイン画面を含むすべての画面を見られます。キーを知らない人・検索ロボットには、存在しないサイトと同じ 404 が返ります |
| 検索エンジンに載せない | `robots.txt` で全拒否、すべての応答に `X-Robots-Tag: noindex`、各ページに `noindex` を設定済み |
| ログイン | **ログインID + パスワード**（IDはメールアドレスである必要はありません）。15 分で 10 回失敗すると一時ブロック |
| LINE の認証情報 | アクセストークン等は暗号化して保存 |

**スタッフへの共有**：管理者が「LINE アカウント管理」画面のアクセス用 URL をスタッフに伝えます（LINE のトークでなく、メールや口頭など安全な方法で）。スタッフは自分の PC・スマホで 1 回開けば、以降はブックマークから `https://line.example.com/` で開けます。
**URL が漏れた・退職者が出たとき**：FTP で `app/config.php` を開き、`'access_key' => '…'` を別の英数字（16 文字以上）に変更します。全員が新しいキー付き URL を開き直す必要があります（同時にパスワードも変更してください）。
**キーを忘れたとき**：管理者としてログインできる端末で確認するか、`app/config.php` の `access_key` を見てください（`https://ドメイン/?k=` の後ろに付けます）。

> **なぜ完全に非公開にはできないのか**：LINE のサーバーが、友だち追加などを知らせる **`/webhook/…`** と、配信画像を取りに来る **`/media/…`** にアクセスできる必要があります。この 2 つだけは、アクセスキーなしでインターネットから届きます。
> - `/webhook/…` は、LINE の署名（チャネルシークレットで計算）が正しくないと何も処理しません。
> - `/media/…` は、32 桁のランダムな ID を知らないと取得できません（配信した画像を、ID を知る人が見られる程度です）。
> 管理画面・友だち情報・配信内容は、アクセスキー + ログインで保護されています。
> なお、**インターネットから届かない場所（事務所内の PC など）では、LINE から Webhook が届かないため使えません**。Xserver などの公開サーバーが必要です。

### その他のセキュリティの目安

- 管理者のパスワードは強固なものにし、スタッフ用には「担当者」（オペレーター）権限のアカウントを個別に作ります。
- 必ず HTTPS でアクセスしてください（Cookie が盗まれにくくなります）。
- アクセス用 URL は SNS・メール転送などで広めないでください。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| `500 Internal Server Error` | `.htaccess` の記述が Xserver に合っていない、または PHP バージョンが古い。PHP を 8.1 以上にする。`app/config.php` を開いて `'debug' => true` にすると画面にエラーが出ます（原因確認後は `false` に戻す） |
| どのページも 404 になる | ① **アクセスキー付きの URL を開いていない**（初回は `https://ドメイン/?k=キー` を開く。キーは `app/config.php` の `access_key`）。② `.htaccess` がアップロードされていない（隠しファイル）。`public_html/.htaccess` があるか確認 |
| 別のパソコン・スマホ・ブラウザでログイン画面が出ない（404） | その端末でまだアクセスキー付き URL を開いていない。キー付き URL を 1 回開く（Cookie を消した場合も同様） |
| セットアップ画面で「データベースに接続できません」 | MySQL ホスト名が違う（`localhost` ではなくパネル記載のホスト名）、ユーザーにデータベースの権限を付けていない、パスワード違い |
| セットアップ画面の ✘（書き込み不可） | `app/` `app/storage/media/` `app/storage/logs/` のパーミッションを 705/755 にする |
| ログイン後すぐログアウトされる | 公開URLが `http` と `https` で混在していないか確認。必ず HTTPS でアクセス |
| 画像のアップロードに失敗する | `app/storage/media/` が書き込み不可。または PHP の `upload_max_filesize` が小さい（縮小後は 1MB 未満なので通常は問題なし） |
| 予約配信が送られない／ダッシュボードに cron の警告 | cron のコマンド（PHP バージョン・パス）が違う。サーバーパネルのコマンドに合わせて修正。`app/storage/logs/last_cron.txt` が更新されているかも確認 |
| LINE の画像・リッチメッセージが表示されない | インストーラーの「公開URL」が実際の URL と違う。`app/config.php` の `base_url` を修正 |
| Webhook の「検証」が失敗する | アカウント接続手順書のトラブルシューティングを参照。URL は HTTPS で外部から開けること（WAF・IP 制限を無効にする） |

### Xserver の「WAF」「海外アクセス制限」について

LINE の Webhook は国内外のサーバーから届きます。サーバーパネルの「WAF設定」で誤検知され Webhook が拒否される場合は、対象ドメインの WAF を一時的にオフにして検証してください。
「国外IPアクセス制限」を有効にしている場合は、LINE からの通信が遮断されることがあるため無効にしてください。
