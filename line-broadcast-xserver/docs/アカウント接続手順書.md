# LINE公式アカウント接続手順書（アクセストークン・Webhook設定）— Xserver 版

各店舗のLINE公式アカウントを、本システム（接骨院 LINE 一括配信）に接続する手順です。
**1 アカウントあたり 10〜15 分**が目安です。8 アカウントなら、アカウントごとに同じ手順を繰り返します。

> 画面の名称・配置はLINE側の更新で変わることがあります。見つからない場合は、メニュー名の近い項目を探してください。

## 0. 事前に必要なもの

| 必要なもの | 備考 |
|---|---|
| 各店舗の LINE 公式アカウント | 管理者権限（LINE公式アカウントマネージャーにログインできること） |
| LINE Developers のアカウント | 公式アカウントの管理者が使う LINE アカウントでログイン（https://developers.line.biz/） |
| 本システムの管理者（`super_admin`）ログイン | アカウント追加は管理者のみ可能 |
| 本システムが Xserver で稼働していること | [Xserver導入手順書](Xserver導入手順書.md) を完了し、`https://{ドメイン}` でログインできる状態（Webhook は HTTPS で外部から到達できる必要があります） |

## 全体の流れ

```
① Messaging API を有効化（公式アカウントマネージャー）
        ↓
② チャネルシークレットを確認（LINE Developers）
        ↓
③ チャネルアクセストークン（長期）を発行（LINE Developers）
        ↓
④ 本システムにアカウントを追加（シークレット・トークンを入力）
        ↓
⑤ Webhook URL を LINE に設定して「検証」→ 利用をオン
        ↓
⑥ 応答設定を整える（公式アカウントマネージャー）
        ↓
⑦ 動作確認（自分のスマホで友だち追加）
```

---

## ① Messaging API を有効化する

すでに Messaging API を利用している（LINE Developers にチャネルがある）アカウントは、②へ進んでください。

1. [LINE公式アカウントマネージャー](https://manager.line.biz/) にログインし、対象のアカウントを開く
2. 右上の「設定」→ 左メニュー「**Messaging API**」を開く
3. 「**Messaging APIを利用する**」を押す
4. **プロバイダー**を選択（または新規作成）して、利用規約に同意する

**プロバイダーについて（重要）**
- 接骨院の全店舗で、**同じプロバイダーを選ぶ**ことを推奨します（例：プロバイダー名「○○接骨院」）。
- プロバイダーは後から変更できません。最初に決めてください。

## ② チャネルシークレットを確認する

1. [LINE Developers Console](https://developers.line.biz/console/) にログイン
2. 対象の**プロバイダー** → 対象の**チャネル**（Messaging API）を開く
3. 「**チャネル基本設定**」タブを開く
4. 「**チャネルシークレット**」の値をコピーして控える（32 文字ほどの英数字）

## ③ チャネルアクセストークン（長期）を発行する

1. 同じチャネルの「**Messaging API設定**」タブを開く
2. 一番下の「**チャネルアクセストークン（長期）**」の「**発行**」を押す
3. 表示された長い文字列をコピーして控える

**注意**
- すでに発行済みで他のシステムが使っている場合、**「再発行」すると古いトークンが使えなくなります**。他のツール（予約システム等）が同じアカウントでトークンを使っていないか確認してから操作してください。
- トークンとシークレットは**パスワードと同じ扱い**です。チャットやメールで共有せず、このシステムの入力欄以外に貼り付けないでください。

## ④ 本システムにアカウントを追加する

1. 本システムに管理者でログイン
2. アカウント一覧の右上「**+ LINE アカウント追加**」を押す（`/channels/new`）
3. 次を入力する

   | 項目 | 入力内容 |
   |---|---|
   | LINE アカウントの表示名 | 店舗がわかる名前（例：渋谷店LINE） |
   | 説明（任意） | 例：渋谷店の予約・お問い合わせ用 |
   | アクセントカラー | 店舗ごとに変えると一覧で見分けやすい |
   | チャネルアクセストークン（長期） | ③でコピーした値 |
   | チャネルシークレット | ②でコピーした値 |

4. 「**LINE アカウントを追加**」を押す
   - 追加時に、LINE へ実際に接続できるか自動で確認されます。
   - 成功すると、そのアカウントの「**設定**」画面に移動します（次の⑤で使います）。

## ⑤ Webhook URL を設定する

Webhook は、**友だち追加・ブロック・受信メッセージを本システムに知らせる仕組み**です。
**設定しないと友だちが本システムに同期されず、タグ配信・ステップ配信が動きません。**

1. 本システムの対象アカウントの「**設定**」画面を開く（⑤の直前に自動で開きます）
2. 「**LINE Webhook URL**」の欄に表示されている URL を「コピー」する
   - 形式：`https://{ドメイン}/webhook/{アカウントごとのID}`
   - **URL の末尾の ID はアカウントごとに異なります。**必ず各アカウントの設定画面からコピーしてください（別店舗の URL を貼らないこと）。
3. LINE Developers Console → 対象チャネル →「**Messaging API設定**」タブ →「**Webhook設定**」
4. 「Webhook URL」に貼り付けて「**更新**」を押す
5. 「**検証**」を押し、「成功しました」と表示されることを確認する
6. 「**Webhookの利用**」を**オン**にする

> 本システムには「アクセスキー」による入口の保護がありますが、**Webhook の URL にはキーを付ける必要はありません**（`/webhook/…` は LINE から直接届くよう、キー無しで開いています。LINE の署名で正当性を確認します）。

## ⑥ 応答設定を整える（公式アカウントマネージャー）

1. 公式アカウントマネージャー → 「設定」→「**応答設定**」を開く
2. 次のとおり設定する

   | 項目 | 推奨 | 理由 |
   |---|---|---|
   | Webhook | **オン** | ⑤で設定した Webhook を有効にする |
   | 応答メッセージ | 運用方針による（本システムでステップ配信を使う場合はオフ推奨） | 自動応答が二重に届くのを防ぐ |
   | あいさつメッセージ | 運用方針による | 本システムの「友だち追加」ステップ配信の 1 通目と内容が重複しないようにする |
   | チャット | オン／オフどちらでも可 | Webhook と併用できます |

## ⑦ 動作確認

1. **自分のスマホ**で、対象アカウントを友だち追加する
2. 本システムの対象アカウント →「**友だち**」に、自分が表示されることを確認する
   - 表示されない場合は、下の「トラブルシューティング」を参照
3. 「タグ」で `テスト` というタグを作り、自分に付ける
4. 「**全店舗 一括配信**」で、そのアカウントだけを選び、オーディエンスを「タグ：テスト」にして配信する
5. 自分のスマホに届くことを確認する（テキストのほか、リッチメッセージ・カードも一度確認すると安心です）

## 担当者（店舗スタッフ）のログイン権限を付ける

店舗スタッフには、**その店舗のアカウントだけ**操作できる権限を付けられます（管理者のみ操作可）。

1. 対象アカウントの「**設定**」画面 →「メンバー」
2. メールアドレスを入力。初めての人は氏名とパスワード（8 文字以上）も入力して追加
3. 追加された人（オペレーター）は、割り当てられたアカウントだけが一覧に表示され、一括配信でも選択できる

## トークン・シークレットを更新する（再発行したとき）

1. LINE Developers で新しいトークンを発行（③）
2. 本システムの対象アカウント →「設定」→「アカウント情報」の認証情報欄に新しい値を入力して保存
   - 保存時に接続確認が行われ、失敗した場合は更新されません
3. 旧トークンはこの時点で使えなくなります。更新までの間は配信が失敗します

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| ④で「LINE への接続に失敗しました」 | トークンまたはシークレットの誤り。コピー時の余分な空白・改行、別チャネルの値、再発行で無効になった旧トークンを確認 |
| ⑤の「検証」が失敗する（401） | チャネルシークレットが違う、または URL の ID が別アカウントのもの。システム側のシークレットを見直す |
| ⑤の「検証」が失敗する（404） | URL の ID が不正（コピー漏れ・文字の欠け）。設定画面から URL をコピーし直す |
| ⑤の「検証」が失敗する（403 など） | アカウントが「無効」になっている。システムの設定画面で「有効」にする |
| ⑤の「検証」がタイムアウト／403 | システムが HTTPS で外部から開けない。Xserver の「WAF設定」で Webhook が拒否されていないか、「国外IPアクセス制限」が有効になっていないか確認する（LINE のサーバーは国外にもあります） |
| 友だち追加しても一覧に出ない | Webhook の「利用」がオフ、または応答設定の Webhook がオフ。⑤⑥を再確認。LINE Developers の「検証」が成功しているか確認 |
| すでに友だちの人が一覧に出ない | 仕様です。Webhook 設定**前**から友だちだった人は、その人が**メッセージを送る／ブロック解除して再追加する**まで把握されません。**「友だち全員」配信**は LINE 側の全友だちに届くので影響を受けません（タグ配信・ステップ配信は把握済みの人だけ） |
| 一括配信の画像・リッチメッセージが表示されない | 画像は本システムの公開 URL から LINE が取得します。インストーラーで入力した「公開URL」（`app/config.php` の `base_url`）が、実際にアクセスする `https://` の URL と一致しているか確認 |
| 予約配信・ステップ配信が送られない | Xserver の「Cron設定」が動いていない。コマンド（PHP バージョン・パス）を確認。ダッシュボード（管理者）とステップ配信画面に警告が出ます（[Xserver導入手順書](Xserver導入手順書.md) の手順 5） |
| 配信が「失敗」になる | 詳細画面のエラー内容を確認。トークン失効、月間メッセージ上限超過（アカウントごと）が主な原因 |
