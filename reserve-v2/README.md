# リカバリー鍼灸院 予約サイト v2（開発中）

現行サイト（`../reserve/` → https://mochizuki-bn3q.vercel.app/ ）のデザインを
そのまま引き継ぎつつ、**空き状況を threease から取得するのをやめて、管理画面で
自分たちで管理する**方式に作り替えたもの。

現行サイトは一切変更していないので、**このフォルダを触っても本番は影響を受けない**。
完成後に Vercel の向き先をこちらへ切り替える。

---

## 現行版との違い

| | 現行版 (`reserve/`) | v2（このフォルダ） |
|---|---|---|
| 空き状況の元データ | threease API | **管理画面で設定した営業時間 − 埋まり枠** |
| 1週間表示の通信 | 7日ぶん 7 リクエスト＋枠ごとの追加問い合わせ | **1 リクエスト** |
| 取得失敗の「?」表示 | あり（threease が落ちると出る） | **不要**（自前データなので失敗しない） |
| メニュー | threease のコース一覧 | **管理画面で登録するメニューマスタ** |
| 予約の受け方 | 公式LINEへ文面を送る | 同じ（変更なし） |

threease への依存が無くなるので、表示が速く、外部要因で崩れない。
代わりに**営業時間と埋まり枠を自分たちで入力する運用**が必要になる。

---

## データの持ち方（Upstash Redis）

すべて `rv2:` 接頭辞。現行システムのキー（`reserve:promos` / `cc:*` / `st:*`）とは
完全に分かれているので、同じ Redis を共有しても壊れない。

| キー | 中身 |
|---|---|
| `rv2:schedule` | 枠の刻み・院ごとの同時施術人数・曜日別の営業時間・臨時休診 |
| `rv2:courses` | メニューマスタ（名前・時間・価格・対象院・対象来院） |
| `rv2:booked:<院>:<YYYY-MM-DD>` | その日の埋まり枠 `{ "10:00": 1, "10:30": 1 }` |
| `rv2:promos` | キャンペーン（現行と同じ仕組み・保存先だけ別） |

### `rv2:schedule` の形

```jsonc
{
  "slotMin": 30,                     // 予約枠の刻み（分）
  "clinics": {
    "192": {
      "capacity": 1,                 // 同時に施術できる人数
      "week": {                      // 0=日 … 6=土。配列＝休憩で分割できる
        "1": [{ "start": "10:00", "end": "13:00" },
              { "start": "15:00", "end": "19:00" }]
      },
      "exceptions": {                // 日付ごとの上書き
        "2026-09-23": { "closed": true },
        "2026-09-24": { "ranges": [{ "start": "10:00", "end": "15:00" }] }
      }
    }
  }
}
```

## 空き枠の決まり方

1. その日の営業時間帯を出す（例外日があればそちらを優先、休診日は枠なし）
2. `slotMin` 刻みで開始時刻を並べる（19:00 終了なら最後の枠は 18:30）
3. 選択中メニューの所要時間ぶんの**連続枠**が空いているかを見る
   - 休憩をまたぐ開始時刻は除外（60分コースは 12:30 開始不可、など）
   - 各枠の埋まり件数が `capacity` 未満であること
4. 開始時刻を過ぎた枠は出さない

`axisAvailable`（営業している枠すべて）も一緒に返すので、埋まっていても
カレンダーの行がずれない。

## API

### 公開

| | |
|---|---|
| `GET /api/availability?clinic=192&start=20260919&end=20260925&course_id=c-xxx` | 空き状況。1週間まとめて取得できる |
| `GET /api/courses?clinic=192&visit=first` | その院・来院パターンのメニュー |
| `GET /api/promos?code=xxxx` | キャンペーン（現行と同じ） |

### 管理（`X-Admin-Password` ヘッダ必須）

| | |
|---|---|
| `GET/POST /api/admin/schedule` | 営業時間・枠の刻み・同時施術人数 |
| `GET/POST/DELETE /api/admin/courses` | メニューマスタ |
| `GET/POST /api/admin/bookings` | 週グリッドの取得 / 枠の開閉 |
| `GET/POST/DELETE /api/admin/promos` | キャンペーン（現行と同じ） |

`POST /api/admin/bookings` は用途別に3通り受け付ける。

```jsonc
{ "clinic":"192", "ymd":"2026-09-23", "time":"10:00" }             // 空き⇄満をトグル
{ "clinic":"192", "ymd":"2026-09-23", "time":"10:00", "delta":1 }  // 1件増やす
{ "clinic":"192", "ymd":"2026-09-23", "times": { "10:00":1 } }     // その日を丸ごと置換
```

## 本番切替の手順（完成後）

1. Vercel で新規プロジェクトを作り、Root Directory を `reserve-v2` にする
2. 同じ Upstash Redis と `ADMIN_PASSWORD` を接続する
3. 管理画面で営業時間・メニューを登録し、別URLで一通り動作確認
4. キャンペーンを `reserve:promos` から `rv2:promos` へコピー
5. 独自ドメイン（または `mochizuki-bn3q`）の向き先を新プロジェクトへ変更
6. 現行プロジェクトはしばらく残しておき、問題が無ければ停止
