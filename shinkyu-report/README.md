# 鍼施術内容書（ミツカル接骨院 → 提携接骨院）

紹介元の接骨院へ渡している「鍼施術内容書」（手書き）を、タブレット・PCで入力して
**A4 1枚の PDF** で出力できるようにしたWebアプリ。

- **Xサーバーに置く**（推奨）：データはサーバーに保存され、4人の端末で共有できる。パスワードでログイン
- **ファイルだけで使う**：`api.php` が動かない場所（パソコンで直接開く・Vercel 等）では、各端末のブラウザ内だけに保存

## できること

- **人体図（前面・背面）をタップ**して施術部位を選択 → ポップアップで詳細入力
  - 施術内容（置鍼／単刺／パルス／灸／円皮鍼）・本数・置鍼時間・ツボ・メモ
  - 選んだ部位は図に番号（①②…）が付き、PDFの「施術内容」欄に一覧で出る
- **人体図は「身体／頭部」を切り替え**：頭部は 顔（前面）・右側面・左側面・後頭部（背面）の4面。
  色・線・塗り・大きさは身体と同じ。両方に印を付けた場合、内容書には両方の図が載る
- **鍼（赤）・電気（青）を人体図に直接付ける**：「鍼を打つ」で刺した位置をタップすると赤い点、
  「電気でつなぐ」で鍼を2つ順にタップすると青い線で結ばれる。もう一度タップで消える。「1つ戻す」あり。
  内容書の表には部位ごとの鍼の本数・電気の組数が入り、図には凡例（● 鍼 ━ 電気）が付く
- 図の横に**部位のチェックリスト**（頭・首／肩／腕／体幹／背中・腰／脚）。図と連動
- 主訴・好転反応・術後の変化・通院指導・申し送りは**定型文ボタン**で入力（設定で編集可）
  → スタッフ間の情報量の差を減らす
- 次回予約日・担当者名
- **プレビュー → PDF保存・印刷**：A4 縦 1枚。文章が多い時は文字と図を自動で縮小して1枚に収める
  （印刷画面で送信先を「PDFに保存」にすると PDF になる。ファイル名は `鍼施術内容書_氏名_日付`）
- 一覧から「**コピーして新規**」：同じ患者様の次回分を、前回の部位・申し送りを引き継いで作成
- **患者様の登録**：内容書に入力した患者様氏名は自動で登録され、次回から入力候補に出る
  （候補から選ぶと、前回の送り元接骨院も自動で入る）。氏名の空白の有無は同一人物として扱う
- **患者様ページ**：その患者様の内容書を新しい順に並べ、主訴・部位・好転反応・術後の変化・次回予約を
  一覧で見返せる。送り元接骨院・スタッフ間メモの編集、「この患者様の内容書を作成」も可能
- **ログ**：内容書の新規作成・コピー作成・PDF出力・削除のたびに、日時・担当者・患者様を記録。
  PDF出力と削除は**その時点の内容も保存**するので、「その時の内容」から送った内容書をそのまま見返し・再出力できる
  （内容書を後から直した・削除した場合でも残る）。操作・担当者・氏名で絞り込み可能

## カルテ枚数計算（`karte.html`）

鍼とは別の機能。レセコンの顧客リスト（CSV・Excel）を読み込み、被りを除いた**本当の顧客数（正確なカルテ枚数）**を出す。
上部メニューの「カルテ枚数」から開く。

- カルテ番号の決まりは「数字」「数字+a」「数字+x」「数字+r（労災）」。**数字の部分が同じものを1枚**と数える
  （例：`125`・`125a`・`125x`・`125r` → 「125」の1枚。全角でも同じ）
- レセコンの書き出し（見出し無し・カルテ番号は `000125` / `000125x` のように6桁0埋め）にそのまま対応。
  先頭の0は無視するので、予約システムの `125` と同じ番号として扱う。カルテ番号・氏名の列は値の形から自動で選ぶ
- 「全カルテ」一覧と検索欄：番号（例：`100`）を入れると `000100`・`000100x` など枝番も含めて表示（重複の確認用）
- ファイルは端末の中だけで計算し、サーバーには送らない
- Shift_JIS／UTF-8 の CSV、Excel（.xlsx）に対応。カルテ番号・氏名の列は見出しから自動で選ぶ（変更可）
- 結果：レセコンの件数／正確なカルテ枚数／枝番をまとめて減った数。予約システムの枚数を入れると差を表示
- 確認用の一覧：まとめたカルテ／同じ氏名で番号が違うもの（二重登録の可能性。自動ではまとめない）／
  決まりと違う番号（125b・125-2 など。入力ミスの可能性）／番号が読めない行
- 正確なカルテ一覧を CSV で保存できる

## 文字のフォント

画面・内容書（PDF）・人体図の文字・カルテ枚数計算はすべて **Noto Sans JP**（Google Fonts から読み込み）に統一。
𠮷・髙・﨑・德・濵・邉・鍼 がすべて表示できることを確認済み（BIZ UD ゴシック・Zen 角ゴシックなどは 𠮷 が無い）。
PDF にはフォントが埋め込まれるので、受け取った側の端末に関係なく同じ見た目になる。
インターネットにつながっていない時は端末のフォントで表示される。

## 4人同時に使っても上書きされない仕組み

- 内容書は **1件ずつ別々に保存**（`localStorage` のキー `shinq:rec:<id>`）。
  全件を1つのデータにまとめて書き換える方式ではないため、別々の内容書を同時に保存しても消えない。
- 各内容書は版番号（rev）を持ち、**同じ内容書を別の画面で更新された場合は自動保存を止めて知らせる**。
  「最新を読み込む」か「自分の入力を別の内容書として保存」を選べる（相手の内容は上書きしない）。
- 患者様（`shinq:pat:<氏名>`）・ログ（`shinq:log:<時刻+乱数>`）も1件ずつ別キー。ログは追記のみで、既存のログは書き換えない。
- 担当者の選択はブラウザのタブごと。1台を交代で使っても担当者が混ざらない。
  一覧は「自分の担当分のみ」で絞り込み可能。

## Xサーバーへの設置

必要なもの：Xサーバーの契約とドメイン（初期ドメイン `xxxx.xsrv.jp` でも可）。PHP 7.4 以上（Xサーバーは標準で PHP 8 系）。

1. **SSL を有効にする**：サーバーパネル →「SSL設定」で使うドメインに無料独自SSLを追加
   （患者様の情報を扱うため必須。`.htaccess` で http は https に自動転送する）
2. **ファイルをアップロード**：このフォルダの中身を、ファイルマネージャーか FTP で
   `ドメイン名/public_html/shinkyu/` などに置く（`.htaccess` と `data/.htaccess` も忘れずに。
   FTP ソフトで「隠しファイルを表示」にすると見える）
   - 置くもの：`index.html` `style.css` `body.js` `fonts.js` `app.js` `sync.js` `api.php` `config.sample.php` `karte.html` `karte.js` `karte.css` `.htaccess` `data/.htaccess`
3. **パスワードを決める**：`config.sample.php` をコピーして `config.php` という名前にし、
   `'password' => 'change-me'` を院内スタッフ共通のパスワードに書き換える（長く推測されにくいもの）
4. ブラウザで `https://ドメイン名/shinkyu/` を開き、パスワードでログインできれば完了
   - 初回アクセスで `data/shinq.sqlite`（データベース）が自動で作られる
   - `https://ドメイン名/shinkyu/data/shinq.sqlite` を開いて「403 Forbidden」になることを確認する（中身が見えないこと）
5. 各スタッフの端末（タブレット等）で同じURLを開いてログイン。ホーム画面に追加しておくと便利

**MySQL を使う場合**（任意）：サーバーパネル →「MySQL設定」でデータベースとユーザーを作り、
`config.php` の `mysql` 欄にホスト名・データベース名・ユーザー名・パスワードを入れる。テーブルは自動で作られる。
SQLite のままでも4人程度の利用なら十分。

### サーバー運用時の動き

- 内容書・患者様・ログ・設定（スタッフ名・定型文など）はサーバーに保存され、全端末で共有される
- 他の端末の変更は約10秒ごと、または画面を開き直した時に自動で取り込まれる
- 画面上部の「同期済み／送信中／オフライン」で状態がわかる（押すとすぐ同期）
- **通信が切れても入力は続けられる**：端末に保存しておき、つながった時に自動で送る
- **同じ内容書を2人が同時に直した場合**、サーバーは先に保存された方を残し、後の人の画面に
  「最新を読み込む／自分の入力を別の内容書として保存」を出す（どちらの入力も消えない）
- ログはサーバー上で追加のみ（変更・削除できない）
- それまで端末内だけで使っていたデータは、その端末で初めてログインした時にサーバーへ送られる
- データのバックアップ：「設定 → バックアップ」の書き出しに加え、`data/shinq.sqlite` をダウンロードして保管する
  （Xサーバーの自動バックアップの対象にもなる）

## ファイルだけで使う場合の注意

データは**各端末のブラウザ内**に保存される（サーバーには送られない）。
- 他の端末の内容書は見えない
- ブラウザのデータ削除・機種変更で消えるため、「設定 → バックアップ（書き出し）」を定期的に行う
  （内容書・患者様・ログをまとめて書き出す。読み込み時は端末にあるデータを上書きせず、足りない分だけ追加）
- ブラウザの保存容量はおよそ 5MB。PDF出力のログは内容書1枚分（数KB）を保存するため、目安として数千回分まで

## 使い方

1. 画面上の「担当者」で自分を選ぶ（初回は「設定」でスタッフ名・送り元の接骨院・定型文を登録）
2. 「＋ 新規作成」→ 入力（自動保存）
3. 「プレビュー」で確認 →「PDF保存・印刷」

## ローカルで動かす

```bash
cd shinkyu-report
cp config.sample.php config.php   # password を書き換える
php -S localhost:8080             # http://localhost:8080 （サーバー同期あり）
```

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 画面 |
| `body.js` | 人体図の部位定義と SVG 描画 |
| `fonts.js` | フォント（Noto Sans JP）の読み込み |
| `karte.html` / `karte.js` / `karte.css` | カルテ枚数計算 |
| `app.js` | 入力・保存・一覧・患者様・ログ・設定・A4 シート生成 |
| `sync.js` | サーバーとの同期（送信待ちの管理・取り込み・ログイン画面） |
| `api.php` | サーバー側（ログイン・データの保存と取得） |
| `config.sample.php` | 設定の見本（`config.php` にコピーして使う） |
| `.htaccess` / `data/.htaccess` | https 転送、データフォルダ・設定見本の非公開 |
| `style.css` | 画面と印刷（A4）のスタイル |
